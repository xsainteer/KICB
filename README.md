# KICB

REST API для работы с клиентами банка, их телефонами, счетами и картами.

## Как запустить

### Требования

- [.NET SDK 10](https://dotnet.microsoft.com/download)
- [Docker](https://www.docker.com/) — для PostgreSQL

### Шаги

1. Запустить PostgreSQL:

   ```bash
   docker compose up -d
   ```

2. Запустить API (в окружении Development база создаётся и миграции применяются автоматически при старте):

   ```bash
   dotnet run --project Presentation
   ```

3. Открыть Swagger UI: <http://localhost:5118/swagger>

Строка подключения — `ConnectionStrings:Database` в `Presentation/appsettings.json`
(по умолчанию совпадает с `docker-compose.yml`).

### Тесты

```bash
dotnet test
```

### Сброс базы

```bash
docker compose down -v
```

## Эндпоинты

| Ресурс | Эндпоинты |
|---|---|
| Клиенты | `GET /api/clients` — список с фильтрацией и пагинацией (`lastName`, `firstName`, `email`, `bornFrom`, `bornTo`, `page`, `pageSize`)<br>`POST /api/clients` · `GET` / `PUT` / `DELETE /api/clients/{id}` |
| Телефоны | `GET` / `POST /api/clients/{id}/phones` · `GET` / `PUT` / `DELETE /api/clients/{id}/phones/{phoneId}` |
| Счета | `GET` / `POST /api/clients/{id}/accounts` · `GET /api/accounts/{id}`<br>`POST /api/accounts/{id}/deposit` · `/withdraw` · `/close` |
| Карты | `GET` / `POST /api/accounts/{id}/cards` · `GET /api/accounts/{id}/cards/{cardId}`<br>`POST /api/accounts/{id}/cards/{cardId}/block` · `/unblock` |
| Переводы | `POST /api/transfers` |

## Архитектурные решения

### Слои

`Domain` (сущности и бизнес-правила) → `Application` (сценарии, интерфейсы репозиториев) →
`Infrastructure` (EF Core, PostgreSQL) → `Presentation` (контроллеры, валидация запросов).

### Богатая доменная модель

Бизнес-правила живут в сущностях: `Deposit`, `Withdraw`, `TransferTo`, `IssueCard`, `BlockCard`, `UnblockCard`,
`Close`. Сеттеры приватные, поэтому сущность нельзя перевести в некорректное состояние снаружи.
`Client` и `Phone` — в основном данные: валидирующий конструктор и `Update(...)`.

### Счёт — агрегат для карт

Правило «у закрытого счёта нет активных карт» затрагивает и счёт, и карты, поэтому они образуют один агрегат
с корнем `Account`: карты выпускаются, блокируются и разблокируются только через счёт.

> **Примечание:** в этом тестовом задании счёт является агрегатом по отношению к картам, но в реальном мире
> карта обычно является агрегатом сама: у неё свой жизненный цикл (лимиты, PIN, перевыпуск, блокировки
> антифрода), и она может быть привязана к нескольким счетам.

### Ожидаемые ошибки — значения, баги — исключения

- Бизнес-исходы (недостаточно средств, разные валюты, активные карты и т. п.) возвращаются как `Result`
  с `Error`, у которого есть стабильный `Code` (например, `Account.InsufficientFunds`).
- Некорректный ввод отсекается на границе API (FluentValidation, 400). Домен дополнительно проверяет инварианты
  через `ArgumentException.ThrowIfNullOrWhiteSpace` и т. п. — если такой ввод дошёл до домена, это баг.
- Ошибки отдаются как ProblemDetails (`application/problem+json`) с полем `code`:
  `NotFound` → 404, `Conflict` → 409, `Validation` → 400.

Рассмотренные альтернативы: исключения для всего, Tester-Doer (`CanWithdraw` / `Withdraw`), `Result`
для валидации ввода.

### Оптимистичная блокировка

У счёта есть теневой столбец `Version` (только в модели EF, не в сущности). `AppDbContext` увеличивает его
при любом изменении счёта или его карт, поэтому параллельные изменения одного агрегата конфликтуют:
второй запрос получает 409 «Concurrency conflict» и должен повторить попытку. Это исключает потерянные
обновления баланса и закрытие счёта одновременно с разблокировкой карты.

### Удаление

- Счета не удаляются, а закрываются; карты не удаляются, а блокируются — история сохраняется.
- Клиента со счетами удалить нельзя (409); при удалении клиента удаляются его телефоны.

### Прочее

- Номера счетов (16 цифр) и карт (16 цифр, контрольная цифра Луна) генерирует банк, а не клиент.
  Карта действует до конца месяца через 3 года после выпуска.
- Полный номер карты не возвращается — только последние 4 цифры.
- Перевод возвращает только счёт-источник: счёт получателя может принадлежать другому клиенту.
- Суммы — положительные, не более 2 знаков после запятой (баланс хранится как `numeric(18,2)`).
- Email уникален без учёта регистра (`citext`).
- Перечисления в JSON — строками; отсутствующее значение перечисления даёт 400, а не значение по умолчанию.
- Доступ к данным — через репозитории и `IUnitOfWork`; репозиторий счёта всегда загружает его карты.
- Сущности создаются конструкторами; фабричный метод есть только там, где создание может завершиться
  бизнес-ошибкой (`Account.IssueCard`).
